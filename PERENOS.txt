Актуально на 26.09.2026

1. ЧТО ЭТО ЗА ПРОЕКТ

LEX — украинский практический справочник по охране труда.

Продукт НЕ использует и не должен использовать AI в пользовательском интерфейсе. Это не чат-бот и не поиск «как Google». Логика продукта:

  раздел → подраздел (тема) → конкретная ситуация → структурированный ответ.

Пользователь выбирает понятную рабочую тему и получает готовый ответ без лишней теории. Ответы пишутся на украинском языке, профессионально, кратко по форме, но полно по смыслу. Не упрощать до школьного уровня, не писать покровительственно и не придумывать требования.

Источники лекций и нормативных актов используются редакционно. В обычном интерфейсе НЕ нужно выводить отдельный список источников/ссылок под каждой ситуацией. Допустимы короткие прямые цитаты с указанием нормы внутри самого текста, когда они действительно усиливают ответ.


2. ТЕКУЩАЯ АРХИТЕКТУРА

Стек: React 19 + TypeScript + Vite 6 + Tailwind CSS 4.
Язык UI и контента: украинский.
Режим данных по умолчанию: mock.
Локальный запуск: npm run dev
Проверки: npm run lint; npm run build

Главные каталоги:

  src/app/             — маршруты, providers, оболочка приложения
  src/modules/         — страницы и UI-модули
  src/domain/          — доменные модели, адаптеры, контракты
  src/mocks/data/      — текущее наполнение справочника
  src/mocks/services/  — mock-сервисы данных
  src/shared/          — общие типы, UI, утилиты
  development data/    — исходные лекции, извлечения, карты предметов

Важные файлы справочника:

  src/domain/referenceSections.ts
      Карта разделов и подразделов публичного справочника.

  src/domain/referenceSituationAdapter.ts
      Адаптирует старую модель WorkingSituation к публичной модели
      ReferenceSituation. Публично показываются только содержательные
      блоки ответа; фиксированных шести этапов нет.

  src/modules/reference/SituationDetailPage.tsx
      Страница одной ситуации. Каждый блок ответа отображается отдельной
      нумерованной секцией. Текст проходит через citationTextToBlocks().

  src/mocks/data/safetyManagementSituations.ts
      Наполнение раздела 01 «Організація охорони праці на підприємстві».

  src/mocks/data/firstAidData.ts
  src/mocks/data/firstAidInstructionBlocks.ts
      Отдельный модуль первой помощи.

  src/shared/types/index.ts
      Общие доменные типы, в том числе WorkingSituation, ReferenceSituation,
      SituationAnswerBlock и FirstAidArticle.


3. ПУБЛИЧНАЯ СТРУКТУРА

В справочнике 17 основных разделов. «Документы» и «Первая помощь» вынесены
в самостоятельные модули, чтобы не дублировать содержание справочника.

Внутри раздела структура свободная:

  Раздел
    → Подраздел / тема
      → Ситуация
        → Столько блоков ответа, сколько реально нужно материалу.

НЕ нужно выдумывать одинаковые «этапы» или одинаковое число карточек.
Ситуации и блоки создаются только там, где есть достаточное содержание.

Карта целевой структуры лежит в корне:

  КАРТА_РАЗДЕЛОВ.md
  МАТРИЦА_ЛЕКЦИЙ.md

Эти файлы нужны как ориентир, но перед изменениями всегда сверять с
src/domain/referenceSections.ts и текущими данными: ранние документы могут
отставать от кода.


4. КАРТЫ ПРЕДМЕТОВ И ЛЕКЦИЙ

Обработаны 21 учебный предмет. Их карты находятся здесь:

  development data/lecture-work/semantic-maps/subject-01/
  ...
  development data/lecture-work/semantic-maps/subject-21/

В каждом subject-XX обычно есть:

  INDEX.md              — краткая навигация по предмету;
  SUBJECT-MATRIX.md     — связь тем предмета с будущими разделами LEX;
  lectures/*.md         — смысловые карты отдельных лекций;
  extracts/lecture-XX/  — извлечённый текст, JSON, заметки и/или изображения;
  SUPPLEMENT-SOURCES.md — дополнительные нормативные и официальные источники,
                          если они нужны для точной редакторской работы.

Исходные файлы лекций лежат в:

  development data/Lessons/

Картами предметов нельзя заменять первоисточник. Они нужны для поиска:
сначала по INDEX.md / SUBJECT-MATRIX.md и картам лекций определить, где
может быть материал; затем открыть извлечение или исходный файл и проверить
смысл. Для нормативных требований, сроков, численности, прав, обязанностей
и других точных утверждений дополнительно сверять действующую официальную
редакцию акта на zakon.rada.gov.ua или на сайте уполномоченного органа.

Некоторые PDF извлекаются с проблемной кодировкой. Не доверять «кракозябрам»
из pypdf как содержанию. Ищите TEXT.md / extracted.json, извлекайте страницы
заново или проверяйте визуально/OCR. Не переносить в LEX непроверенный текст.


5. КАК НАПОЛНЯТЬ СПРАВОЧНИК

Работать последовательно, по одному разделу. Сначала сделать одну эталонную
ситуацию, проверить её в браузере, затем применять формат к остальным.

Алгоритм для одной ситуации:

  1) Открыть текущую структуру раздела в src/domain/referenceSections.ts.
  2) Найти ситуацию в src/mocks/data/ или добавить её в профильный файл.
  3) По картам предметов определить релевантные лекции и извлечения.
  4) Прочитать исходный материал по смыслу, а не только искать совпадение
     слов в вопросе.
  5) Для правовых/нормативных деталей проверить действующий официальный акт.
  6) Написать структурированную украинскую ответную карточку.
  7) Проверить, что каждый блок отвечает на отдельный практический аспект,
     а не повторяет соседний.
  8) Запустить npm run lint, npm run build и проверить страницу в локальном
     браузере на http://localhost:3000.

Формат хорошей содержательной ситуации:

  - короткое точное summary;
  - обычно 5–9 самостоятельных блоков, если материала достаточно;
  - в каждом блоке — тезис и его практическое раскрытие;
  - короткие прямые цитаты из нормы допускаются точечно;
  - без искусственного раздувания текста;
  - без вымышленных сроков, ролей, форм документов и «универсальных» правил.

Пример эталона: «Положення про службу охорони праці» в разделе 01.
Он содержит девять блоков: роль документа, модель службы по численности,
подчинение, задачи, функции, права, границы ответственности, взаимодействие
и актуализация. Его формат следует считать ориентиром по глубине, но не
копировать механически на темы, где материала меньше.

ВАЖНО: SituationDetailPage.tsx применяет к тексту старый нормализатор
извлечённых цитат. Он воспринимает конструкцию «пробел — пробел» (длинное
тире с пробелами) как маркер списка. В связном авторском тексте не использовать
такое тире: лучше написать полное предложение, использовать запятую или
короткое тире без пробелов. После каждого нового длинного текста обязательно
проверять визуальное отображение.


6. ТЕКУЩЕЕ СОСТОЯНИЕ РАЗДЕЛА 01

Раздел: «Організація охорони праці на підприємстві».
Подразделов: 18.
Ситуаций в текущем наполнении: 19.
Файл данных: src/mocks/data/safetyManagementSituations.ts.

Раздел уже перенесён из старой шестиэтапной модели в свободные блоки ответа,
но большинство ситуаций пока короткие — по 3 абзаца. Следующая большая задача:
расширить остальные ситуации раздела 01 до разумной глубины по образцу
«Положення про службу охорони праці», используя карты предметов и нормативные
источники.

Перезаполненная эталонная ситуация:

  slug: polozhennia-pro-sluzhbu-okhorony-pratsi
  URL:  /reference/polozhennia-pro-sluzhbu-okhorony-pratsi
  данные: src/mocks/data/safetyManagementSituations.ts

Для неё использованы:

  - ст. 15 Закона Украины «Про охорону праці»;
  - Типовое положение о службе охраны труда, приказ №255;
  - извлечения subject-12, в частности lecture-01 и lecture-06.

Не менять остальные ситуации раздела 01 без отдельного редакторского
прохода: старые короткие ответы принадлежат предыдущему этапу наполнения.


7. ПЕРВАЯ ПОМОЩЬ

Это отдельный модуль /first-aid, а не часть 17 разделов справочника.
Сейчас заполнены 23 учебные карточки:

  боевые действия / военное положение;
  первичная оценка;
  отсутствие сознания и дыхания, СЛР, обструкция дыхательных путей;
  массивное кровотечение;
  травмы, ожоги, электротравма;
  холод, перегревание, отравления, утопление;
  анафилаксия, судороги, инсульт, боль в груди, гипогликемия.

Карточки имеют три слоя: «Дійте негайно», пояснение техники/контроля и
запреты. Детальная логика вынесена в firstAidInstructionBlocks.ts, а не
смешана с UI. Медицинский контент должен обновляться только после сверки с
действующим приказом МОЗ №441 и официальными материалами МОЗ. Не добавлять
медицинские указания «по памяти».


8. ВАЖНЫЕ ПРАВИЛА РАБОТЫ

  - Не добавлять AI/API/семантический поиск в пользовательский продукт.
  - Не выводить отдельную библиографию или ссылки на лекции в карточках
    справочника. Ссылки/источники нужны внутреннему редактору.
  - Не создавать ситуацию только потому, что она есть в карте разделов.
    Нужна подтверждённая содержательная база.
  - Не вставлять большие необработанные цитаты лекций. Сначала извлечь смысл,
    затем дать структурированный рабочий ответ; короткая цитата допустима,
    когда нужна точная правовая формулировка.
  - Не использовать устаревшие НПА без проверки статуса и актуальной редакции.
  - Не менять одновременно структуру, UI и большой массив контента без
    необходимости. Сначала качество содержания, затем только нужные изменения.
  - Не полагаться на CURRENT_STATE.md для фактического наполнения: этот файл
    частично устарел. Текущее состояние определяют исходники и данная передача.


9. ПРОВЕРКА ПЕРЕД ЗАВЕРШЕНИЕМ ПРОХОДА

  [ ] Прочитаны релевантные карты и исходные извлечения.
  [ ] Нормативные факты сверены с действующим официальным источником.
  [ ] Нет дублирования с модулем документов или первой помощи.
  [ ] Ответ профессиональный, не сухой и не разговорный.
  [ ] Блоки не повторяют друг друга и не имеют искусственного числа.
  [ ] В интерфейсе нет ложных списков/разрывов из-за символов извлечений.
  [ ] Выполнены npm run lint и npm run build.
  [ ] Страница визуально проверена на локальном сервере.


10. БЛИЖАЙШАЯ ЗАДАЧА

Продолжить раздел 01. После подтверждения эталонного формата расширять его
ситуации по порядку: сначала подраздел «Служба охорони праці», затем остальные
подразделы. Каждую ситуацию наполнять на основании карт предметов и
проверенных нормативных положений, а не путём механического увеличения текста.
