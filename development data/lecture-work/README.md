# Обработка лекций → справочный контур

Рабочая папка учёта.

**Корпус (с 2026-09):** `../Lessons/` — **21 папка-предмет**, файлы по темам/лекциям (PDF / PPTX / DOCX), не монолитные PDF.  
Извлечённый текст: `../Lessons/extracted/` (пересобирается с нуля; сейчас может отсутствовать).

Очередь `_queue.*` сброшена вместе со старыми монолитами — будет заново под папки 1–21 и карты лекций.  
В `lectures/` оставлен **архив densify** по трём старым источникам (аудит цитат уже в mock); extract под ними больше нет.

## Три контури довідника (магазин)

1. **Розділ (кошик)** — широкий 1-й контур (`SituationCategoryGroup` / `REFERENCE_SECTIONS`). Лекції **не** є розділами.
2. **Ситуація (товар)** — 2-й контур усередині розділу.
3. **6 етапів** — 3-й контур усередині ситуації (підготовка… покращення).

Редакційне дерево 1–2 контурів (з прив’язкою лекцій до ситуацій): **[HIERARCHY.md](./HIERARCHY.md)**.

Розміщення з лекції: спочатку ситуація + етап + підрозділ; розділ обираємо за предметною полицею (охоплення > компактність). Порожні розділи в каталозі дозволені.

## Основной режим: путь 1 (лекция → справочник)

Идём **по одной лекции/файлу предмета** (после карты корпуса). На каждый рабочий кусок спрашиваем: *какой вопрос справочника (ситуация / этап / підрозділ) это закрывает?* Кладём туда **плотную цитату**. Следующие лекции могут **дописывать** тот же підрозділ.

**Путь 2** (підрозділ → все лекции) — только точечно, когда видна дыра после пакета лекций. Не как основной проход по корпусу.

## Договорённости

1. **Лекция-first** — по карте предмета / файлам. Лекция не `done`, пока есть `unassigned` **или** рабочие темы остались тонкими тезисами вместо плотных цитат.
2. **Уплотнение (обязательно):**
   - в підрозділ кладём **полный ответ на его вопрос** из этого места лекции (абзац, перечень, алгоритм, сроки, кто делает) — не заголовок слайда и не 1–2 строки «для галочки»;
   - один блок = одна тема; длинный раздел → несколько блоков;
   - лёгкий cleanup переносов/OCR — да; вольный пересказ — нет;
   - не 100% страниц лекции в UI, но и не ~2% текста: всё операционно полезное из лекции должно попасть в blocks + справочник (или явно `deferred_learning` / `discarded` с причиной).
3. **Второй режим** — после лекции (или пакета) короткий gap-check по этапам затронутых ситуаций.
4. **Учебный контур** — в последнюю очередь (`deferred_learning`).
5. В продукт / verified НПА — **не** публикуем из архива без человеческой проверки.
6. Новые ситуации/секции — **кандидаты** (`proposed` / `draft`), без раздувания каталога без ревью.
7. Тип блока **«Посилання на …»** — обязательный учёт связей (бланки, терміни, суміжні ситуації, джерела на перевірку).
8. Дубли между лекциями — не копировать тот же смысл второй раз; дописать более полной цитатой или отметить в blocks «уже в sit-X».
9. Конфликт с уже лежащим mock/НПА — в отчёт + `editorialNote`, не молчаливый overwrite устаревшим текстом лекции.

Память проекта: `content.md` + `blocks.json` + `situationsData` (не «весь корпус в чате»).

## Статусы лекции (`processingStatus`)

| статус | смысл |
|---|---|
| `pending` | ещё не начали |
| `in_progress` | идёт разбор / уплотнение |
| `done` | рабочие блоки учтены плотно; нет `unassigned`; тонкие заглушки закрыты или явно отложены |
| `blocked` | ждём OCR / решение владельца |

## Статусы блока внутри лекции

| статус | смысл |
|---|---|
| `unassigned` | ещё не разложили |
| `placed` | ушёл в существующую ситуацию/этап/секцию |
| `proposed` | предложена новая ситуация или секция |
| `deferred_learning` | только для учебного контура позже |
| `ocr_queued` | рисунок/скан |
| `discarded` | не для LEX (причина обязательна) |

## Файлы

- `HIERARCHY.md` — дерево 1–2 контуров (легенда старых `stableId` — устарела до перемаппинга).
- `lectures/<id>/` — архив blocks/отчётов по старым монолитам + будущие карточки по новым источникам.
- `maps/` — **карты корпуса**: `_MASTER.md` / `_master.json` + `subjects/<id>/MAP.md` + `map.json`.
- `maps/_extract_cache/` — кэш текста страниц (пересборка карт без повторного парсинга).
- `build_lecture_maps.py` — генератор карт (без LLM): `python build_lecture_maps.py`.
- `harvest_section_sources.py` — поперечний збір джерел для розділу з карт: `python harvest_section_sources.py`.
- `sections/<id>/` — PLAN + SOURCES для наповнення розділу (старт: `01_preparation_admission`).
- (пізніше) черга обробки під усі 21 предмети.
