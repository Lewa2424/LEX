# SCHEMA — строка размещения (placement row)

Один блок лекции → одна строка в таблице резолюции. Таблица живёт в `resolutions/`, не в mock.

## Идентификаторы

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `block_id` | string | да | Стабильный id: `{subject}-{lecture}-{seq}` например `s12-l01-b003` |
| `source_path` | string | да | Путь к TEXT.md / extract относительно `development data/` |
| `lecture_id` | string | да | Напр. `subject-12/lecture-01` |
| `seq` | int | да | Порядок блока внутри лекции, с 1 |

## Якоря фраз (не page-only)

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `from_phrase` | string | да | Уникальный (в пределах файла) фрагмент **начала** блока, дословно из текста |
| `to_phrase` | string | да | Уникальный фрагмент **конца** блока, дословно |
| `page_hint` | string\|null | нет | Подсказка страницы/слайда, если есть в extract; не источник истины |

Инвариант: повторный прогон нарезки по тем же `from_phrase`/`to_phrase` должен находить тот же отрезок. Если фраза неоднозначна — удлинить якорь.

## Содержание блока

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `excerpt` | string | да* | Текст блока (*в пилоте можно держать в `cuts/`, в таблице — короткий preview) |
| `excerpt_preview` | string | да | 120–240 символов для таблицы |
| `block_type` | enum | да | см. ниже |

### `block_type`

- `norm` — требование / правило / норма (кандидат в цитату ситуации)
- `definition` — определение термина
- `procedure` — пошаговый порядок действий
- `form_ref` — бланк / журнал / акт (ссылка или структура)
- `context` — фон, не карточка сама по себе
- `noise` — титул, оглавление, мусор нарезки

## Вопрос (смысл карточки)

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `catalog_question_id` | string\|null | нет* | id из `QUESTION_CATALOG_v0.md` |
| `proposed_question` | string\|null | нет* | новый вопрос, если каталог не покрыл |
| `question_final` | string\|null | после резолюции | итоговая формулировка для UI / title ситуации |

\* Хотя бы одно из `catalog_question_id` | `proposed_question` для типов кроме `noise`/`context` (если идут в карточку).

Правило продукта: **нет вопроса — нет info-карточки** в довіднику.

## Полка (куда кладём)

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `section_id` | string\|null | после полки | slug раздела 1-го контура (`electrical_safety` …) |
| `situation_slug` | string\|null | после полки | существующая или предлагаемая ситуация 2-го контура |
| `phase_id` | enum\|null | для цитат | один из 6: `preparation` … `improvement` |
| `placement_mode` | enum | да | `new` \| `replace` \| `append` \| `skip` |

- `new` — новая ситуация (или новый термин / бланк — см. `target_kind`). **Предпочтительный режим**, если вопрос читателя свой, даже если рядом уже есть похожая карточка в том же разделе.
- `replace` — существующая карточка, но в UI сейчас **шаблонный/обрубленный скелет**: заменить этап ответа лекцией (**lecture-first**). Не `append` вниз. См. `INSERT_RULES.md`.
- `append` — дополнить **уже живую** ситуацию цитатой / підрозділом (тот же вопрос, без обрезки сверху).
- `skip` — не в продукт (noise, истинный дубль в том же підрозділі, вне scope)

| Поле | Тип | Описание |
|---|---|---|
| `target_kind` | enum | `situation` \| `term` \| `form` \| `none` |
| `proposed_subsection` | string\|null | новый підрозділ внутри ситуации, если темы нельзя смешивать в одном |

### Политика расширения полок (владелец)

1. Не сжимать разные вопросы читателя в одну карточку «ради компактности».
2. Почти-дубли на **разных** карточках (в т.ч. в одном разделе) — допустимы, если формулировки вопросов различаются.
3. Новый підрозділ — нормальный исход, не исключительный.

### Порог объёма для НОВОЙ ситуации (`MIN_CHARS_NEW_SITUATION = 2000`)

Защита от пустых карточек в довіднику.

| Правило | Как считать |
|---|---|
| Что суммируем | Длины `excerpt` (символы Unicode) всех блоков с `target_kind=situation`, одним `situation_slug` (в т.ч. `proposed_*`), без `noise` / явного `skip` |
| Когда считаем | Перед шагом **insert** новой ситуации в `src/mocks` |
| Порог | Сумма **> 2000** → можно создавать карточку; **≤ 2000** → оставить кандидатом (`proposed` / копить текст из следующих лекций), либо владелец явно снимает порог |
| Предмет 1 (ОП из технологического курса) | Порог **не обязателен** для узких ОП-карточек: см. INSERT_RULES п.5. Качество = полный ответ на вопрос, не длина |
| `append` к уже существующей | Порог **не** применяется (короткая цитата в живую карточку — ок) |
| `term` / `form` | Свой здравый смысл; порог 2000 — про ситуации-карточки 2-го контура |

В таблице резолюций поле `notes` может содержать `chars_for_slug=N` / `below_min_chars` — чтобы рецензент B и владелец видели накопление.

## Резолюция и качество

| Поле | Тип | Описание |
|---|---|---|---|
| `confidence` | float 0–1 | уверенность предложения (нарезка / агент / человек) |
| `resolution` | enum | `pending` \| `approve` \| `revise` \| `reject` |
| `resolution_by` | string\|null | `human` \| `agent-a` \| `agent-b` \| id |
| `resolution_note` | string\|null | кратко почему |
| `status` | enum | `draft_cut` \| `proposed` \| `resolved` \| `inserted` \| `blocked` |

Только `resolution=approve` + явный шаг insert → запись в `src/mocks`. После insert: `status=inserted` и ссылка `mock_ref` (slug / term id).

| Поле | Тип | Описание |
|---|---|---|---|
| `mock_ref` | string\|null | куда вставлено после approve |
| `verification` | enum | для норм из лекции по умолчанию `under_review` |

## Формат файла резолюции

Рекомендуемый пилот: Markdown-таблица в

`resolutions/{subject}-{lecture}-placements.md`

или CSV/TSV с теми же колонками, если строк много.

Минимальные колонки пилота:

`block_id | from_phrase | to_phrase | block_type | catalog_question_id | proposed_question | section_id | situation_slug | phase_id | placement_mode | target_kind | confidence | resolution | status | notes`

## Нарезка (спека v0 для этапа C/D)

1. Источник: `TEXT.md` (или эквивалент extract) одной лекции.
2. Блок = связный смысловой кусок (норма / определение / процедура), не «страница целиком».
3. Типичный размер: 2–12 предложений; дробить простыни НПА.
4. Якоря `from_phrase` / `to_phrase` уникальны в файле.
5. Выход нарезки: файл в `cuts/` + строки со `status=draft_cut` в `resolutions/`.
6. Скрипт нарезки (этап E) **только** пишет draft; не трогает mock.

## Связь с 6 этапами

Цитата ситуации всегда в одном `phase_id`. Если блок закрывает несколько этапов — **несколько строк** (копии block_id с суффиксом `-p2` или отдельные block_id), не одна строка с массивом фаз.
