# Muscle pipeline — наращивание «мышц» довідника из лекций

Отдельный контур учёта. **Не** смешивать сырые нарезки и резолюции с `src/mocks` до статуса `approve` → insert.

Связан с общим режимом path-1 в [`../README.md`](../README.md).

## Роли

- Владелец (визионер): границы продукта, спорные полки, политика approve.
- Инженер (агент-исполнитель в Cursor): форматы, скрипты, пилоты, insert по approve.
- Агенты резолюции: **пока не запускаем** (этап позже). Общий контекст — файлы в этой папке, не «магия одного чата».

## Структура папки

```
muscle-pipeline/
  README.md                 — этот файл
  SCHEMA.md                 — контракт строки размещения
  QUESTION_CATALOG_v0.md    — расширяемый список вопросов-кандидатов
  INVENTORY.md              — корпус и пилотный источник
  STATUS.md                 — текущий шаг конвейера
  cuts/                     — нарезки текста по файлам предмета
  resolutions/              — таблицы block → вопрос → полка → резолюция
  reports/                  — аудиты, счётчики, спорные
  pilots/                   — материалы пилотных прогонов
```

## Жёсткие правила

1. Ситуация = формулируемый вопрос читателя.
2. **Расширяем каталог намеренно.** Внутри существующих разделов не стесняться `new` (новая карточка), если у читателя свой вопрос. Почти-дубли между разными карточками — ок. Почти-дубли **в одном** підрозділі одной карточки — нет (тогда `append` или объединить текст).
3. **Підрозділ** внутри ситуации — можно предложить новый, если иначе получится простыня или смешение тем.
4. Список вопросов — **расширяемый** (`proposed_question` допустим; потом внести в каталог).
5. **Защита от пустых карточек:** новую ситуацию в продукт (`insert`) создаём только если накопленный полезный текст для неё **> 2000 символов** (см. SCHEMA). Предлагать `new` в таблице резолюций можно раньше — карточка ждёт накопления или решения владельца.
6. **Insert ≠ append вниз.** Если карточка — обрубленный densify-скелет → `replace` (лекция сверху). Правила: [`INSERT_RULES.md`](./INSERT_RULES.md).
7. Без `approve` владельца нет записи в `src/mocks` (кроме явного запроса «заполни и покажи в UI»).
8. Нормы из лекций → `under_review`, не verified НПА.
9. Рецензенты A/B работают по SCHEMA; insert соблюдает INSERT_RULES.
