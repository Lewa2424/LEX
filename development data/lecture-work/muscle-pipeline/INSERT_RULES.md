# INSERT_RULES — как класть результат агентов в довідник

Урок пилота s01-l01: агенты нарезали и «дописали» правильно по таблице, но в UI сверху остался **обрубленный шаблон** старого массового наполнения. Владелец увидел «дыры», а не лекцию.

## Обязательные правила insert

1. **Lecture-first.** Подразделы с текстом лекции должны быть **первыми** в этапе ответа (обычно `preparation` / «Зміст відповіді»).
2. **Не append под скелет.** Если у карточки `looksLikeTruncatedTechSkeleton` (или аналог): summary с «Не дублює картку…», обрывы на «Від» / «, де», шаблон «у довіднику з … пояснює Тема» — режим **`replace`**, не `append`.
3. **`replace`** = заменить содержимое applicable-этапа ответа на согласованные підрозділи + переписать `summary` (без шаблонного «не дублює»).
4. **`append`** только если карточка уже «живая» (лекционные/редакционные підрозділи без обрезки) и новый кусок — тот же вопрос.
5. **`new`** — по SCHEMA (порог > 2000 символов); новые карточки сразу без densify-скелета.
   **Исключение — предмет 1:** курс технологический, ОП-контент из него тонкий по природе. Для узких ОП-карточек с контекстом предмета 1 порог 2000 **не обязателен**: достаточно полного ответа на вопрос читателя (процедурный текст без мета-блоков). Владелец 2026-10-12: «по этому предмету так».
   **Предмет 2 (екологічні ризики…):** целиться **2000+** символов полезного текста на карточку. Меньше 2000 — только если вопрос важный и обязан быть закрыт (явно помечать в resolutions). Владелец 2026-10-12.
6. Цитаты из архива лекций → поле `status: under_review` в данных; **не** писать `under_review` / «не verified НПА» / «наповнення з архіву» в `summary` и видимый lead-текст для читателя.
7. После insert владелец должен открыть карточку и **сразу** видеть смысл для читателя, а не служебный жаргон пайплайна.
8. **Запрещены в публичном UI** (страницы `/reference`, каталог, шапки карточек): фразы про «обов’язкові етапи», densify, «Не дублює картку…», английские статусы, пояснения внутренней модели данных. Такие вещи — только в admin / docs / данных со strip в адаптере.
9. **Фильтр ОП:** в продукт только то, что отвечает на вопрос охраны труда / безопасности работ (ризик, допуск, ЗІЗ, документи, хто відповідає, аварійна дія). Чиста технологія процесу («що таке металургія / руда / флюс») без безпекової рамки → `skip` / архів нарізки, не insert. Пилот s01-l01 знято з вітрини саме через це.
10. **Много карточек — хорошо.** В одном підрозділі (теме) может быть множество ситуацій. Человек приходит за **конкретным ответом на конкретный вопрос**, а не читать простыню лекции «в надежде понять». Аналогия владельца: чтобы завести машину, не нужно читать инструкцию по её созданию. Предпочтительный режим — узкая `new`-карточка на свой вопрос читателя; `append` только когда это **тот же** вопрос, а не соседний.

## Режим `placement_mode` (дополнение к SCHEMA)

| mode | Когда |
|---|---|
| `new` | Новая ситуация |
| `replace` | Существующая, но контент — обрубленный/шаблонный скелет |
| `append` | Существующая живая карточка, тот же вопрос |
| `skip` | Не в продукт |

Агент B и insert-скрипт обязаны выбирать `replace`, если сработал детектор скелета.
